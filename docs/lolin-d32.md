Суммарный допустимый ток по 3V3 для внешней периферии: LDO отдаёт максимум 500 мА [L], часть из них уходит на сам ESP32 при работе Wi-Fi/BLE; реальный запас под датчики **[не проверено]**. Ток одного GPIO: типично 40 мА источник на пин (VDD3P3_CPU/RTC) по [M], Table 14; суммарные пределы **[не проверено]**.

Нужная нам периферия (PMS5003 ~100 мА, 5 В) питается от VBUS (5 В по USB), не от 3V3.

### Светодиоды

| LED | Схема | Источник |
|---|---|---|
| LED2 | 3V3 -> R9 2 кОм -> LED -> **GPIO5**; светит при GPIO5 = LOW (active low). В wiki: `LED_BUILTIN = GPIO5`. GPIO5 при этом strapping-пин | [S], [W], [G] |
| LED1 (зарядка) | VBUS -> R6 2 кОм -> LED -> вывод CHRG TP4054 (open drain); к GPIO не подключён | [S], [T] |

Цвета светодиодов (какой красный, какой синий) **[не проверено]**: ни схема, ни wiki их не указывают. Логика: красный (если зарядный) = LED1, управляется только TP4054; GPIO5 управляет другим LED2.

**Тусклый красный без батареи.** Если красный = LED1 (зарядка), то по [T] CHRG притянут к земле только пока идёт заряд; при отсутствии батареи (на выводе BAT на плате стоит 10 мкФ, C2) «светодиод быстро мигает»: глазом это выглядит как тусклое свечение. Это нормальное поведение индикатора заряда, а не неисправность платы или питания. Что красный именно LED1 **[не проверено на плате]**. Подключили LiPo: LED горит во время заряда, гаснет по его окончании [T].

### Батарея

- Делитель на ADC: VBAT -> R12 100 кОм -> **GPIO35** -> R17 100 кОм -> GND, то есть V(GPIO35) = VBAT / 2 [S]. GPIO35 = ADC1_CH7, вход-only, на заголовок не выведен [G], [S]. ADC1 работает при включённом Wi-Fi [G].
- Напряжение батареи измеряется по формуле VBAT = 2 x V(GPIO35) (ослабление/калибровка ADC в ESPHome настраиваются отдельно **[не проверено]**).
- Вывод VBAT (JP1-16) и VBUS (JP1-15) на заголовке [S].

GPIO6-11 (flash модуля) на заголовок не выведены; нельзя использовать [M], [G]. GPIO35 (батарея) и GPIO5 (LED) не свободны.

Сводка ограничений ESP32:

- GPIO6-11: flash, не использовать [M], [G].
- GPIO34-39: только вход, нет программных pull-up/pull-down [G]. Кнопкам на них нужен внешний резистор.
- Strapping: GPIO0, GPIO2, GPIO5, GPIO12 (MTDI), GPIO15 (MTDO) [E], [G]; лучше не вешать на них нагрузку, влияющую на уровень при сбросе.
- ADC2 (GPIO0, 2, 4, 12-15, 25-27) недоступен при Wi-Fi [G]; у нас Wi-Fi всегда включён.

## 3. Что умеет плата в проекте

Текущая прошивка: `esphome/lolin-d32-btproxy.yaml` (ESPHome 2026.9.1, esp-idf), имя `btproxy-kitchen`: Wi-Fi, API, OTA, BLE-прокси с `active: true`, `cache_services: false`, скан 320 мс / 300 мс.

Что нужно знать о BLE-прокси [B], [K]:

- Wi-Fi и BT делят одно 2.4 ГГц радио и одну антенну. Большое окно скана вредит Wi-Fi; в [K] дефолты рекомендованы, изменение `interval`/`window` обычно пользы не даёт.
- Одновременных активных GATT-подключений по умолчанию 3 (`connection_slots`), максимум 9, рекомендация не больше 5; каждый слот ~1 КБ RAM [B]. Для чайника нужен один слот на время команды; пассивные рекламные пакеты (BTHome и т. п.) от слотов не зависят [B].
- BLE-стек сильно расходует RAM; рекомендуется не раздувать конфигурацию [K].
- Сборка со всеми модулями станции даёт RAM 58.4 % (72704 из 124580), Flash 76.4 % (1401503 из 1835008) (compile на сервере 65.21.40.51; чистый прокси: 54.4 % / 62.9 %). Работа всех модулей вместе под нагрузкой **[не проверено]**.

Модульная конфигурация: `esphome/station-d32.yaml` + `esphome/d32/*.yaml`. В верхнем файле включается каждый модуль отдельной строкой (`display`, `input`, `rfid`, `scale`, `air`); без них получается чистый прокси. Проверено `esphome config` для всех 32 комбинаций модулей.

## 4. Распиновка станции на D32 и отличие от ESP32-S3

Используются только свободные пины: не flash (6-11), не UART0 (1, 3), не strapping (0, 2, 5, 12, 15), не GPIO35 (батарея). GPIO34/36/39 (только вход) оставлены в запасе. Код: `esphome/d32/*.yaml`.

| Узел | Сигнал | D32 | S3 (`station.yaml`) |
|---|---|---|---|
| SPI (PN532) | CLK | GPIO18 | GPIO12 |
| | MOSI | GPIO23 | GPIO11 |
| | MISO | GPIO19 | GPIO13 |
| | CS | GPIO4 | GPIO10 |
| I2C (SSD1306 0x3C, SGP41 0x59, SHT41 0x44) | SDA | GPIO21 | GPIO8 |
| | SCL | GPIO22 | GPIO9 |
| HX711 | DT | GPIO32 | GPIO4 |
| | SCK | GPIO33 | GPIO5 |
| Энкодер EC11 | A | GPIO25 | GPIO6 |
| | B | GPIO26 | GPIO7 |
| Кнопки (на GND) | OK (SW энкодера) | GPIO27 | GPIO15 |
| | BACK | GPIO14 | GPIO17 |
| | TARE | GPIO13 | GPIO16 |
| PMS5003 | RX <- TXD датчика | GPIO16 (UART2 RX) | GPIO18 |

Заметки к выбору:

- SPI и I2C на штатных пинах VSPI и I2C ESP32 (18/19/23, 21/22) [E]. GPIO5 (штатный CS VSPI) не взят: strapping + LED.
- HX711 на GPIO32/33 (ADC1, но здесь как цифровые), энкодер на 25/26: оба с pull-up. GPIO34-39 не годятся для кнопок/энкодера без внешних подтяжек [G].
- GPIO14 и GPIO13 для кнопок: у них есть JTAG-функции, но без отладчика это не мешает; на GPIO14 в момент загрузки возможен короткий сигнал **[не проверено]**. Кнопки нажаты только вручную, на старт не влияют.
- Батарейный делитель (GPIO35) и LED GPIO5 не пересекаются с занятыми пинами.
- PMS5003 питается от 5 В (VBUS); логика 3.3 В, поэтому подключён только TXD датчика -> GPIO16. PMS5003 RXD не подключён.
- Все IO 3.3 В [W]; PN532, SSD1306, SGP41, SHT41, HX711, энкодер питаются от 3V3; суммарный ток от LDO 500 мА [L].

Различия с S3: все пины пересчитаны, потому что у S3 заняты GPIO26-32 (flash) и GPIO33-37 (octal PSRAM N16R8) (см. шапку `station.yaml`), а у D32 запрещены GPIO6-11 и strapping-пины; в D32 нет PSRAM и USB на GPIO19/20 (нет блока `psram`, `board: lolin_d32` вместо `esp32-s3-devkitc-1`, нет `flash_size`); батарейный ADC и LED у S3-devkit в конфиге не использовались. Скан BLE тот же 320/300 мс. `power_save_mode: none` из S3-конфига в `base.yaml` не включён, чтобы не менять уже прошитый прокси; при нестабильности связи включить в `base.yaml`. Модуль `air` на D32 использует `uart_pm` на GPIO16 вместо GPIO18.

PN532 в SPI-режиме (DIP/перемычки на модуле). Предложенный `POST /v1/tags/scan` в 3d-api пока не реализован (rfid.md §3.6, предложение): модуль `rfid.yaml` помечен так же.
