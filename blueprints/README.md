# Kettle power pulse (blueprint `kettle_auto_off.yaml`) и Kettle plug keep on (`kettle_plug_keep_on.yaml`)

Останавливает нагрев чайника Yunmi Kettle (`custom_components/yunmi_kettle`) на целевой температуре через
умную розетку и держит розетку включённой по умолчанию. Сущности по умолчанию: `sensor.kettle_water_temperature`,
`sensor.kettle_status`, `sensor.kettle_keep_warm_target_temperature` (зеркалит температуру активного профиля).

## Как работает

Чайник сам греет до 100 °C и сам на цели не останавливается. Блюпринт:

1. Вода дошла до `цель - offset` при включённой розетке и статусе из `heating_statuses`.
2. Розетка выключается, через `restore_after_seconds` (по умолчанию 2 с) включается обратно: импульс питания,
   нагрев останавливается. Уведомление «Kettle ready» (persistent и/или `notify_service`).

**Удержание температуры блюпринт и импульс не включают.** По данным теста после импульса чайник стоит в `standby`
и остывает. Удержание чайник включает сам только после собственного цикла (по спецификации режим 3/1 «после
кипячения»: закипел -> остыл до температуры профиля -> держит, статусы `boil_keepwarm`/`heat_to_set`), либо кнопкой
keep warm на самом чайнике. Включить нагрев или удержание по BLE нельзя (README opravdin/hass-yunmi-kettle-ble:
нагрев запускается только кнопкой). Проверка на живом чайнике, режим 3/1 «без кипячения» (`siid 3 piid 1` = 1,
записи пока нет ни в компоненте, ни здесь): возможно, чайник сам греет только до температуры профиля и держит; см.
шаги в отчёте.

### Предиктивный таймер (задержка опроса)

Опрос идёт раз в 16 с (быстрый режим), вода за это время греется на 6 °C. Поэтому на каждом новом чтении во время
нагрева блюпринт считает скорость нагрева и время до порога `t = (цель - offset - T) / скорость`. Если `t` не
больше `poll_period_seconds` (20 с), ставится таймер на `t - latency_seconds - возраст чтения`, и по нему сразу
делается импульс, не дожидаясь следующего чтения.

- Скорость: скользящее среднее (вес 0.5) по последним чтениям, хранится в `input_number.kettle_heat_rate`,
  в начале нагрева сбрасывается на `heat_rate_default` (0.39). Одно чтение может изменить оценку не больше, чем
  на -30 % / +40 %; точка отбрасывается при интервале вне 4-90 с или скорости вне 0.05-1.5 °C/с.
- Таймер отменяется новым чтением (считается заново), сменой статуса, выключением розетки, снятием флага armed.
  Недоступный датчик (unavailable/unknown) тоже отменяет таймер.
- `latency_seconds` 1.4 и `heat_rate_default` 0.39 взяты из таблицы выше (одна серия). Оценка зависит от
  объёма воды: при другом объёме скорость пересчитывается по чтениям уже на втором чтении.
- Результат на фейках (скорость 0.39 °C/с, offset 3.5): импульс при истинной температуре 71.4 °C. Без таймера он
  случился бы на первом чтении >= 71.5, то есть при ~74.5 (в этом сценарии) с перелётом до +6 °C.
- Если в первом чтении вода уже выше порога, срабатывает прежний триггер по порогу.

### Статусы

Enum компонента: `standby`, `heating`, `boil_keepwarm`, `heat_to_set`, `cooling`, `abnormal`. По умолчанию
«нагрев» = только `heating`. Собственное удержание чайника в живых данных выглядит как `boil_keepwarm` (подогрев
до заданной температуры, 22:55:50, вода 71 -> 74) и `heat_to_set` (вода достигла 75, 22:58:56). Эти статусы
блюпринт не должен считать нагревом: в первой версии (все три статуса) в 22:56:26 импульс выключил питание
чайника на удержании при 72 °C (чайник ушёл в `standby`, потом удержание включилось снова). Исправлено в
`heating_statuses`; `binary_sensor.kettle_keep_warm_active` = статус `boil_keepwarm` или `heat_to_set`.

### Защита от повторных импульсов (гистерезис)

- Триггер по фронту (false -> true): пока вода выше цели, повторно не срабатывает.
- Флаг `armed_entity`: импульс только когда флаг включён. Импульс (и любое выключение розетки) флаг выключает.
  Включается снова: когда вода остыла на `rearm_drop` (3 °C) ниже порога `цель - offset`; когда в нагреве (статус
  `heating`, розетка on) чтение ниже порога минус 1 °C; при старте HA.
- Блюпринт ничего не нагревает сам. Чайник после импульса не греет обратно при падении до 74 °C: в тесте он остывал
  без подогрева (82 -> 72). Повторный импульс возможен только в новом нагреве (кнопка на чайнике).

### Failsafe

`max_heating_minutes` (15): розетка on + статус из `heating_statuses` + вода ниже порога + флаг armed непрерывно
N минут -> розетка выключается и не возвращается (уведомление «Kettle failsafe»), флаг
`input_boolean.kettle_failsafe_tripped` включается ДО выключения. Сбрасывается включением розетки (рукой, в HA или
физически) или выключением самого хелпера.

### unavailable / unknown

Нечисловая температура, unavailable/unknown статус дают «ложь» во всех условиях: розетка не включается и не
выключается. Цель недоступна: override (если задан и режим `override`), иначе `fallback_target` (75).

### Быстрый опрос во время нагрева

Компонент только опрашивает чайник (60 с по умолчанию), уведомления в сущности не попадают. Блюпринт поэтому сам
запускает опросы, пока идёт нагрев: каждые `fast_poll_seconds` вызывает `homeassistant.update_entity` на датчике воды.
Для `yunmi_kettle` это реальный BLE-опрос: `CoordinatorEntity.async_update` вызывает
`coordinator.async_request_refresh()` (проверено по исходникам HA и по DEBUG-логу на живом чайнике).

- Старт: розетка включилась, либо статус из `heating_statuses` при включённой розетке.
- Остановка: прошло `fast_poll_max_minutes` (60) от старта; либо статус `standby` (после 60 с на первое
  обновление); либо розетка выключена дольше, чем идёт импульс (`restore_after_seconds` + 10 с). Максимум 60 мин:
  после этого опрос возвращается к базовому.
- Только один цикл: флаг `poll_active_entity` (`input_boolean.kettle_poll_active`). Флаг, висящий дольше
  `fast_poll_max_minutes + 2 мин`, считается выключенным. При старте HA флаг сбрасывается. **Если перезагрузить
  автоматизации (`automation.reload`) или отредактировать её во время нагрева, цикл обрывается с включённым флагом:
  выключите `input_boolean.kettle_poll_active` вручную.**
- unavailable/unknown: пауза между опросами не меньше 30 с.
- Реальная частота: один BLE-опрос около 6 с (5.83 и 5.67 с на живом чайнике), `DataUpdateCoordinator` не обновляет
  чаще, чем раз в 10 с, реальный период около 16 с (в таблице 15.4-16.2 с).
- Базовый интервал интеграции не менялся: 60 с. Увеличивать его до 300 с небезопасно: нагрев начинают кнопкой на
  чайнике при уже включённой розетке, его обнаружит только очередной опрос.

## Kettle plug keep on (`kettle_plug_keep_on.yaml`): розетка включена по умолчанию

Вторая автоматизация из отдельного блюпринта включает розетку, когда она «вернулась», и уважает намеренное
выключение failsafe.

- Обрыв питания или связи: переход розетки `unavailable` -> `off`: пауза 4 с, затем `switch.turn_on`, до 3 попыток с
  паузой 10 с (если уже включена или поднят флаг failsafe, останавливается).
- Старт HA: ждёт, пока розетка станет доступной (до 2 мин), если она `off` и флаг failsafe не стоит, включает так же.
- Ручное выключение в HA: переход `on` -> `off` не из unavailable, ничем не отменяется (розетка остаётся выключенной).
  Но при перезапуске HA или обрыве питания выключенная вручную розетка будет включена: «по умолчанию включена».
- Failsafe: пока `input_boolean.kettle_failsafe_tripped` включён, розетка не включается ни при обрыве питания, ни при
  старте HA. Флаг сбрасывается включением розетки (любой способ) или выключением хелпера руками.
- Импульс питания блюпринта не пересекается: он не создаёт переход из unavailable.

На самой розетке (Tuya Smart Socket 16A, `product_id` 3nprwiontzyzpzng) настройки «состояние при включении питания»
нет: в диагностике устройства только DP `switch_1` и `countdown_1` (и измерения). Поэтому по умолчанию
включённой её делает эта автоматизация; настройка в приложении Smart Life возможна, если устройство её даёт (из
Tuya cloud API в HA она не видна). Переход на tuya-local (HACS, local_key из Tuya IoT, профиль розеток 16A)
сделал бы DP видимым, но не нужен для этой автоматизации.

## Хелперы

- `input_boolean.kettle_heat_armed` (initial on): флаг импульса;
- `input_boolean.kettle_poll_active`: флаг цикла быстрого опроса;
- `input_boolean.kettle_failsafe_tripped`: failsafe выключил розетку (после перезапуска HA состояние сохраняется);
- `input_number.kettle_heat_rate` (0..5 °C/с, шаг 0.001): оценка скорости нагрева.

Для второй розетки нужны отдельные хелперы (указать во входах).

## Настройка самого чайника (сделано, блюпринт ничего не пишет в чайник)

Для удержания на стороне чайника: `switch.kettle_keep_warm_after_boil` = on и
`number.kettle_profile_N_keep_warm_time` = 60 (N = `select.kettle_active_profile`). Выставлено для профиля 5:
было 720 мин и выключатель off, стало 60 мин и on. (По спецификации (3,2) это «переключатель памяти удержания»,
а режим «после кипячения / без кипячения» (3,1) в HA не выведен.)

## Создать автоматизацию

UI: Settings -> Automations & scenes -> Blueprints -> «Kettle power pulse at target temperature» и «Kettle plug keep
on» -> Create automation, выбрать «Smart plug». Остальные входы имеют рабочие значения.

YAML (`automations.yaml`):

```yaml
- alias: Kettle power pulse
  use_blueprint:
    path: kettle/kettle_auto_off.yaml
    input:
      switch_entity: switch.<plug_entity_id>
      # необязательно: restore_after_seconds: 2, offset: 3.5, max_heating_minutes: 15,
      # fast_poll_seconds: 10, fast_poll_max_minutes: 60, poll_period_seconds: 20,
      # latency_seconds: 1.4, heat_rate_default: 0.39, target_mode: override,
      # target_override: input_number.kettle_target, notify_service: notify.mobile_app_<phone>
- alias: Kettle plug keep on
  use_blueprint:
    path: kettle/kettle_plug_keep_on.yaml
    input:
      switch_entity: switch.<plug_entity_id>
```
